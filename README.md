# PrepMate: AI Study Pack Generator

Upload lecture notes, PDFs, slides or spreadsheets (or paste text) and get an exam-prep study pack: summary, flashcards, multiple-choice quizzes, short-answer questions and essay prompts, all generated by AI.

## Features

- Google sign-in
- Upload **PDF, TXT, DOCX, PPTX, XLSX** (max 10 MB) or paste text
- AI-generated summary (short / medium / long), topics, flashcards (5-20), MCQs (3-50), 5 short-answer questions, 3 essay prompts
- Difficulty setting (Easy / Medium / Hard)
- Dashboard with search, topic filters, difficulty badges and hover preview
- Flashcard progress ("Mastered" / "Need review") with a Study Again filter
- Quiz scoring and quiz history
- "Explain selection" for any text in the summary
- Export a pack as text, or export flashcards as printable coloured sticky notes
- Light / dark / system theme
- Profile page

## Tech stack

| Layer | Tech |
| --- | --- |
| Frontend | React, Vite, Wouter, TanStack Query, Tailwind CSS, shadcn/ui, Framer Motion |
| Backend | Node.js, Express 5, TypeScript |
| Database | PostgreSQL (Supabase) with Drizzle ORM |
| Auth | Passport.js + Google OAuth 2.0, sessions stored in Postgres |
| AI | Groq (`llama-3.3-70b-versatile`) |
| File parsing | `pdf.js-extract` (PDF), `mammoth` (DOCX), `jszip` (PPTX), `exceljs` (XLSX) |

## Prerequisites

- Node.js 20 or newer
- A [Supabase](https://supabase.com) project (free tier is fine)
- A [Groq](https://console.groq.com) API key
- A Google Cloud OAuth 2.0 Client ID

## Local setup

```bash
git clone https://github.com/PreciousNoah/study-pack.git
cd study-pack
npm install
cp .env.example .env     # then fill in the values (see below)
npm run db:push          # creates the database tables
npm run dev              # http://localhost:3000
```

On Windows PowerShell use `copy .env.example .env`.

## Environment variables

| Variable | Description |
| --- | --- |
| `DATABASE_URL` | Supabase Postgres connection string (see notes below) |
| `GROQ_API_KEY` | Groq API key |
| `GOOGLE_CLIENT_ID` | Google OAuth client ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth client secret |
| `SESSION_SECRET` | Long random string used to sign session cookies |
| `PORT` | Server port (default 3000 locally) |
| `NODE_ENV` | `development` or `production` |
| `APP_URL` | Public URL of the site. In production this must be the URL users visit, and the Google callback URL should be built from it |

Generate a session secret:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### Database notes (Supabase)

- Find the connection string under **Project Settings, Database, Connection string**.
- If the password contains special characters, URL-encode them (`@` becomes `%40`, `#` becomes `%23`, `$` becomes `%24`) or use a simple alphanumeric password.
- For the running app, use the **transaction pooler** (port `6543`). The session pooler (port `5432`) has a small client limit and causes `MaxClientsInSessionMode` errors.
- For `npm run db:push`, use the **session pooler / direct** connection (port `5432`).
- Free Supabase projects are paused after a period of inactivity. If the app was idle for a while, open the Supabase dashboard and restore the project first.

## Google OAuth setup

1. Go to [console.cloud.google.com](https://console.cloud.google.com), then **APIs & Services, Credentials, Create credentials, OAuth client ID** (type: Web application).
2. Add these under **Authorized JavaScript origins** and **Authorized redirect URIs**:

| | Local | Production |
| --- | --- | --- |
| Origin | `http://localhost:3000` | `https://YOUR-DOMAIN` |
| Redirect URI | `http://localhost:3000/api/callback` | `https://YOUR-DOMAIN/api/callback` |

3. Copy the client ID and secret into `.env`.

## Deployment

### Option A: everything on one host (simplest)

Deploy the whole app to Render, Railway or similar. The production server serves both the API and the built frontend.

- Build command: `npm install && npm run build`
- Start command: `npm start`
- Set all environment variables above, with `NODE_ENV=production`
- The server must listen on `0.0.0.0` and use the platform's `PORT`

### Option B: frontend on Vercel, backend on Render

The Express backend is a long-running server (sessions, file uploads up to 10 MB, AI calls that can take a while), so it should stay on Render or Railway. Vercel serves the frontend and **proxies `/api` to the backend**, so the browser only ever talks to one domain. That avoids CORS and cross-site cookie problems.

**1. Backend on Render**

- New Web Service, connect the repo, root directory empty
- Build: `npm install && npm run build`
- Start: `npm start`
- Environment variables as in the table above, with `APP_URL=https://YOUR-VERCEL-DOMAIN`
- Note the backend URL, for example `https://study-pack-backend.onrender.com`

**2. Frontend on Vercel**

- Import the repo, root directory is the repo root (not `client`)
- Framework preset: Other
- Build command: `npx vite build`
- Output directory: `dist/public` (check `build.outDir` in `vite.config.ts` and match it)
- Edit `vercel.json` and replace `YOUR-BACKEND` with your Render URL

`vercel.json`:

```json
{
  "buildCommand": "npx vite build",
  "outputDirectory": "dist/public",
  "rewrites": [
    { "source": "/api/:path*", "destination": "https://YOUR-BACKEND.onrender.com/api/:path*" },
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

**3. Finish**

- Update the Google OAuth origins and redirect URIs to your Vercel domain (see above)
- In production the session cookie must be `secure: true` and Express needs `app.set("trust proxy", 1)`
- Using a custom domain: add it in Vercel, then update `APP_URL` on Render and the Google OAuth entries

Render's free tier sleeps when idle, so the first request after a quiet period can take 30-60 seconds.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `ENOTFOUND` with a weird hostname | Special characters in the DB password. URL-encode them or simplify the password |
| `MaxClientsInSessionMode` | Use the transaction pooler (port 6543) for `DATABASE_URL` |
| `ENOTSUP` on startup (Windows) | Listen on `localhost` locally and `0.0.0.0` in production; do not use `reusePort` |
| `NODE_ENV is not recognized` (Windows) | Use `cross-env` in the scripts (already set up) |
| Port already in use | `npx kill-port 3000` |
| "Application failed to respond" | Server must bind `0.0.0.0` and use `process.env.PORT` |
| `npm install` fails with `EJSONPARSE` | `package.json` has duplicated or stray content; it must be one valid JSON object |
| PDF returns no text | Scanned/image-only PDFs have no extractable text (OCR is not supported) |
| Login redirects to the wrong place | The OAuth callback URL does not match the redirect URI registered in Google |
| Everything fails after a long idle | Check the Supabase project is not paused, and that the Groq key is still valid |

## Security

- Never commit `.env` (it is in `.gitignore`)
- If keys were ever committed or pasted somewhere public, rotate them: new Groq key, new Google OAuth client secret, new Supabase database password
- Add rate limiting before opening the app to the public (an earlier attempt was reverted because of database connection issues)

## Known limitations

- Avatar uploads are not saved to the database yet (they reset on refresh)
- The AI is asked for key concepts, but they are not stored or shown yet
- Only the first ~20,000 characters of a document are sent to the AI
- Scanned PDFs are not supported
